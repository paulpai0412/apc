LOCAL OPERATION GUIDE / CEMENT WORKSPACE

AuTHRity 新手操作手冊

從「打開哪個網址」開始，學會啟動、看懂資料、做研究，最後才進入有權限保護的控制流程。

目前環境：Linux／WSL2研究與 Runtime 分開單一 HTML，可離線閱讀

依據程式版本 9805c54 與 2026-10-30 的本機介面核對。這是操作說明，不會自動檢查服務、不會登入、不會送出控制命令；按鈕僅導航、複製文字或整理閱讀內容。

先知道這個界線

這台工作區是隔離的合成水泥磨環境，不是工廠。畫面中的「現場運行／現場 OPC」是功能名稱；此處來源實際為本機模擬。任何工廠連線、參數與接管，都需要另外投運、審查及授權。

    01 / START HERE

    先開網址；打不開才啟動

    同一套原 React 介面，分成兩個服務入口。網址最後的數字是連接埠，不要省略，也不要改成常見的 3000 或 5173。

    MODELING / 43180

    研究與模擬入口

    匯入資料、清洗、辨識模型、調參、執行閉環模擬及送審。新手先從這裡認識資料。

    開啟研究介面（新分頁）http://127.0.0.1:43180/

    左側應出現 M1–M9。研究工作可能保存檔案或持續運算，但不因此取得 Runtime 控制權。

    RUNTIME / 43181

    監測與控制入口

    看設備、趨勢、事件與控制資格。有權限的人才可核准、接管或安全交還。

    開啟 Runtime（新分頁）http://127.0.0.1:43181/

    左側應出現 R1–R7。第一次只看，不要按 Arm、Engage、交接或重連。

    編寫時兩個網址均實際回應 HTTP 200；這是當時的檢查結果，不是現在仍在線的保證。127.0.0.1 表示目前這台電腦，不能把同一網址當成另一台電腦的入口。

    1. 用瀏覽器開啟需要的入口

      在這台 Windows／WSL2 主機，可先用 Windows 的 Edge 或 Chrome 開啟上述網址。研究與 Runtime 的登入狀態各自管理；在一邊登入，不保證另一邊已登入。切換模式按鈕若停用，請開啟另一個入口，不要嘗試解除隔離。

      成功標準：看到 AuTHRity 登入頁，或已登入的 M／R 功能導覽。

    2. 登入隔離練習環境

      在「帳號」「密碼」輸入管理者交付的帳密，按「登入」。由目前準備腳本初次建立的本機測試帳號為 admin／admin；僅限此明確隔離範例，不能用於正式部署。若帳密已變更，使用管理者提供的新帳密，不要刪除帳號資料庫或反覆重設。

      本機啟動器使用的測試帳密檔位於 /home/timmypai/cement-v4/test-credentials.json；獨立核准者由管理者另行提供帳號。不要把帳密檔上傳 GitHub 或貼進問題回報。

      成功標準：左下角顯示目前帳號／角色，頁面來源與預期入口相符。角色是 Admin 也不代表擁有所有控制群組授權。

    3. 如果網址打不開，在 Ubuntu／WSL 終端啟動

      先確認這台已準備好的工作區沒有在執行；若已有服務，直接使用，不要重複啟動。從 Windows Terminal 選擇 Ubuntu，進入 Bash 後貼上下列完整區塊。不要直接貼在 PowerShell 或 Windows 命令提示字元。

      Bash｜只啟動已準備好的 cement-v4
      (
  export PATH="/home/timmypai/.local/share/authrity/native-validation/bin:$PATH"
  /home/timmypai/cement-v4/venv/bin/python -B \
    /home/timmypai/cement-v4/source/validation/cement_workspace/workspace.py \
    start --root /home/timmypai/cement-v4
)

      這個指令使用已準備的 Python、程式快照及資料庫。PATH 是找工具的目錄清單；此行讓啟動器找到這台機器的 Wine／PostgreSQL，不會安裝系統軟體。程式會在前景持續執行，請保留該終端。

      成功標準：輸出 RESEARCH UI http://127.0.0.1:43180/、RUNTIME UI http://127.0.0.1:43181/，後續沒有 BLOCKED/FAILED，且 Runtime 可查到實際原生狀態。只看到網址不代表原生啟動已成功。

    4. 分清楚「程式目錄」與「運行資料」

      位置用途
      /home/timmypai/apps/AuTHRity-APCGit 程式碼、文件及這份 HTML。git pull 不會自動重建既有工作區。
      /home/timmypai/cement-v4已準備的程式快照、二進位、資料、登入資料庫及驗證證據。不要刪除，也不要在這裡重新執行 prepare。

      若這兩個路徑不存在，或你是從 GitHub 剛下載到另一台電腦，請交由管理者按 安裝／重建程序準備。不要猜一個空目錄直接 start。

    啟動受阻時不要強行清除鎖

    「連接埠被使用」「launcher lock」「原生 authority socket」是防止重複寫入的重要訊息。先找出原服務。不要 killall、刪 socket／lock、重設 journal，或為了能啟動就加上 --recover-monitor。恢復程序見 事故後恢復。

    02 / UNDERSTAND THE SYSTEM

    系統在幫你做什麼？

    把水泥磨想成一台需要穩定品質的機器。系統先用歷史資料理解「調整進料或分離器後，產品會怎麼變」，再用模型計算下一步建議。只有通過獨立核准及控制資格檢查後，才允許把建議送進下層控制。

    依數字 1–6 閱讀。手機或較窄視窗可在流程圖內左右滑動；整份頁面不需橫向捲動。

    研究模式：先證明，不碰控制

    CSV 或 PostgreSQL 提供歷史；清洗產生可追溯版本；辨識得到模型；調參比較控制方案；原生 Session 真正計算閉環。最後保存候選供審查，不是直接下載到正在運行的控制器。

    Runtime：真實時間的控制循環

    採集器讀取本機 OPC 訊號 → 原生 APC 引擎檢查品質與資格 → 求解下一步 → 僅在獲授權的 Engage 派送 → 由獨立應用回授核對結果。HMI 是操作與觀察介面，不是求解器。

    兩種時間不可混淆：季度模擬可用虛擬採樣時鐘加速；Runtime 必須等待真實新資料。本範例控制週期為 60 秒、目前模型要求 49 筆合格歷史；暖機以實際資格為準，不能加速動畫或修改 Ts 來假裝通過。

    03 / FIRST VISIT

    第一次先做這六件事

    這一輪只練習觀看與導航，不建立研究工作，也不改動 Runtime。完成勾選只是手冊閱讀記錄，不是系統檢查或操作授權；重新整理會清除。

    已閱讀 0 / 6 項；這不是系統資格檢查。

    畫面怎麼看

    • 左側導覽：切換功能頁，不會啟停控制。
    • 頁首：先看來源、模型／Epoch、觀測時刻及品質，再看數值。
    • 設備選取：選設備，再選其綁定點位；沒綁定、沒有量測就不能當成現場讀值。
    • 曲線：CV／MV／DV 各有工程尺度。共用時間游標對齊時間，不代表不同單位可以共用數值大小。

    3D 與手機／鍵盤

    • 可用「重設／全廠」「聚焦所選設備」「向左環繞」「向右環繞」「放大」「縮小」等按鈕調整視角。
    • 用 Tab 移動焦點、Enter 啟動按鈕；「設備（支援鍵盤）」可用選單操作，不必精準點 3D。
    • 手機由左下「功能」開啟選單；單指／雙指手勢只是改視角與縮放。
    • 設備動畫、流向粒子、收合設備都屬於顯示；不會推進或暫停原生 Session。沒有量測的風機／轉動不應被理解為正在運轉。
    04 / MODELING FUNCTIONS

    M1–M9：研究端每一頁做什麼

    使用研究入口。可儲存研究資料，但不會因研究頁的任何核選或候選選擇而取得 Runtime 寫入權。

    M1研究總覽與任務找研究版本、run 與正在執行的工作。

    選擇已有研究或 run，查看目前階段、完成數、狀態及下一步。新手先查看既有完成結果，不必重新跑整個季度。

    • queued 是排隊，running 是執行中，completed 才是工作完成。
    • 需要停止研究時使用明確取消操作，等伺服器確認 cancelled；關閉瀏覽器不會取消。
    • failed 要看失敗報告，不能把部分結果改稱完成。完成也不代表所有資格通過。
    M2資料來源與快照從歷史資料開始，保留原始內容和來源。
    • CSV / History JSON 檔案：選本機 UTF-8 CSV 或符合契約的 History JSON。匯入後核對筆數、欄位及原始資料集 ID；相同內容可能去重，不一定增加一份。
    • PostgreSQL：只能選伺服器設定的來源白名單，指定 UTC 時間區間；不是在瀏覽器輸入任意資料庫帳密。
    • 匯入唯讀採集快照與來源 manifest：上傳資料及來源描述檔兩者。manifest 用來證明來源、時間、唯讀屬性與內容雜湊；不是自己隨便補一個檔名。
    • 原始檔不會因後續清洗而被覆寫。尚未清洗的資料不等於可以直接辨識。
    M3設備、點位與工程契約定義各訊號的物理意義、單位與界線。

    核對 CV／MV／DV、目標、操作界線、工程硬界線、MV 最大步幅，以及 MV 歷史是否真的代表下層 PID 的有效 SP。不要把量測範圍當成安全極限。

    設備視圖需明確確認設備型式、拓樸與點位綁定，另存不可變版本。由有效且已確認的 trial 建立設備配置；若尚無 trial，先完成研究，再返回補上設備綁定。

    研究工程設定不修改 Runtime profile。化驗延遲、單位或實體量意義不清楚時，保存草稿並請工程人員確認。

    M4清洗與工況整理對齊時間、角色、品質，再保存可用資料。

    選原始資料，設定時間欄位／格式、採樣時間、訊號欄位及角色、單位、scale／offset、品質欄位。再設定重複值、缺值、離群處理、時間切分與工況區間。

    按「預覽清理結果」，查看原始／清洗曲線、警告與「資料可用」。確認後按「儲存清理資料並用於研究」。只有預覽，還不是已保存版本。

    補值只能依合法規則處理短缺口，不能偷看未來或跨切分；未解決缺口不要硬補到看似完美。

    M5模型辨識與資格估計製程反應，檢查模型是否真的適用。

    先有已保存的研究版本，再依伺服器能力選 FIR、FOPDT 或 SOPDT 控制模型族及 evaluation plant。按畫面的「辨識並凍結 … 控制模型」，查看產物 ID、SHA-256、辨識報告及 qualification。

    FIR 用一系列反應係數；FOPDT 是一階加延遲；SOPDT 是二階加延遲。模型族不同，不能只因名稱熟悉就認定合格。激勵不足、共線、預測誤差或尾端未穩定都可能被拒絕。

    資格失敗要補資料或修正研究，另建新版本；不可把失敗當零增益、放寬門檻只為得到綠燈，或用最終留出資料反覆挑選勝者。

    M6MPC 設定與自動調參在固定條件與有限預算內比較控制折衷。

    設定採樣時間、控制方法、預測／控制範圍、權重搜尋界線、情境、輪數及試驗上限。先按「儲存不可變研究版本」，再依資料與模型資格按「啟動有界研究」。

    一個 study 是固定研究條件；一次執行叫 run；run 裡各組參數叫 trial。需要比較時應固定資料、模型、目標、硬界線與評分條件，不要一面看結果一面改考題。

    開發試驗不等於每次都跑完整季度；已驗證範例的開發驗證切分為 40,320 筆，凍結候選後才做 129,600 掃描的季度評估。

    M7閉環模擬與壓力驗證區分封存讀取與真正新的原生模擬。
    • 已記錄試驗 A/B：查看既有結果；移動時間游標不是重新求解。
    • 新模擬與工作階段：綁定有效凍結 trial、情境、傳輸路徑及需要的設備版本後，按「建立凍結模型工作階段」。
    • 使用「單步推進」或「啟動伺服器連續執行」；需要停下時按「本批完成後暫停」，等待確認。需要再跑時明確恢復，不因換頁自動恢復。
    • 「伺服器每批掃描數」是計算批次，不是把原控制 Ts 改短。關頁、收合設備、轉動相機不會停止工作。
    • 結果未知時按「查詢原操作結果」，不要重送。成功看 Session 身分、實際掃描數及終態，不看 3D 動畫有沒有動。
    M8比較、候選與送審保存精確候選，還沒有控制權。

    一起看 CV 偏差、變異、越限與 MV 動作代價。run 完成且方法建議為 candidate_for_review 才能送審；低分不等於可採用。

    選可送審方法及唯讀清單內的精確 Runtime 目標，勾選「我了解此版本僅供工程審查，沒有工廠控制權限」，按「保存精確目標的候選送審版本」。

    成功標準：「已保存審查版本 · 尚未授權控制」，附不可變版本 ID、模型雜湊及目標。後續需 R6 獨立核准。

    M9持續研究政策進階功能：限制什麼時候可以再研究。

    綁定已保存研究與凍結模型，設定新資料／漂移觸發、品質條件、持續窗口、冷卻時間及 run／trial 總預算，再保存政策 revision。能力未宣告時不能要求重新辨識。

    啟用後查看排程、去重、跳過及資格失敗原因。暫停政策只停止新的研究觸發，不取消已經執行的 run，也不停止 Runtime。

    新手先保持暫停。M9 不是自動發布；Runtime 的有界發布是 R6 的另一份政策及獨立授權。

    05 / RESEARCH SOP

    自己做一次：資料 → 模型 → 候選

    以下只對本機合成資料操作。若只是熟悉畫面，先用 M1 選既有完成的 run、M7 選「已記錄試驗 A/B」，不必建立新工作。自行重跑會產生你的版本與 ID，不要求與影片一致。

    從 GitHub 下載的人也有同一份範例

    repo 的 validation/examples/cement-v4/ 保留工作區 data/ 全部七個原始檔案。可使用這裡的 原始 CSV 代替下方本機絕對路徑，依同一套 M2／M4 步驟匯入。清洗範本、工程與情境設定、來源及 SHA-256 一起提供；完整清單見 README。這些是合成資料，不是資料庫備份，也不是可直接啟動的工作區。

    1. M2：匯入已提供的範例 CSV

      選「CSV / History JSON 檔案」，從本機選取以下檔案，確認格式為「CSV · 含欄位標題」、填好「資料集名稱」，再按「匯入並前往清理」。Windows 檔案選擇視窗可直接貼上 UNC 路徑。

      Windows 檔案選擇視窗中的路徑
      \\wsl.localhost\Ubuntu\home\timmypai\cement-v4\data\cement-2026-q1-raw.csv

      Linux：/home/timmypai/cement-v4/data/cement-2026-q1-raw.csv。這是 2026-01-01 至 2026-04-01、不含終點的合成歷史，原始 129,601 列含一筆明示重複。

      成功標準：能選到匯入的原始資料集，欄位符合下一張表。相同 bytes 去重屬正常，不需改檔名騙過系統。

    2. M4：對應欄位，再預覽清洗

      時間欄位選 time_seconds，格式選秒數；採樣時間填 60 秒。quality 是品質欄位，不是 CV。此合成 CSV 的 OPC DA Good 值為 192，不要將所有來源的品質代碼一律解讀成 192。

      CSV 欄位角色白話意義單位欄位輸入值
      ProductFinenessCV產品細度，希望控制的品質m2/kg
      MillDifferentialPressureCV磨機差壓，希望穩定的量mbar
      FreshFeedMV可調的新鮮進料有效 SPt/h
      SeparatorSpeedMV可調的分離器速度有效 SPrpm
      ClinkerHardnessDV可量測但不能直接操控的熟料硬度kWh/t
      FeedMoistureDV可量測但不能直接操控的進料含水率%

      本機 data/cleaning.json 範本使用 scale=1、offset=0、重複時間保留最後一筆、只向前沿用過去值、最大缺口 120 秒、無額外離群濾除；訓練結束相對秒數 2678400，驗證結束 5097600。這些是此範本的設定，不是所有工廠通用規則。

      按「預覽清理結果」，核對時間順序、訊號、缺口與品質，再按「儲存清理資料並用於研究」。不要把預覽畫面當已保存。

      成功標準：顯示資料可用、清洗版本 ID；此例去重後 129,600 列，依時間分成 44,640／40,320／44,640 筆訓練／驗證／測試資料。

      到 M6 檢查目標、情境、方法、輪數、試驗上限及搜尋界線，給研究可辨識的名稱，按「儲存不可變研究版本」。已保存版本不直接修改；改條件就另存新版本。

      成功標準：取得 study／研究版本 ID，並知道此時還沒有啟動工作。範例設定與影片 trial 都不能當作所有研究的通用最佳值。

    4. M5：辨識並核對 qualification

      選剛保存的研究，依能力選控制模型族及 evaluation plant，按「辨識並凍結 … 控制模型」。展開 report，確認模型 ID、雜湊及資格結果。

      成功標準：可追溯的模型產物，且所需資格通過。只出現模型檔、不代表適合控制。若失敗，先補資料或請工程人員處理，不直接往下走。

    5. M6、M1：啟動有界研究，等待真實完成

      回 M6 確認凍結版本，再按「啟動有界研究」。到 M1 選該 run 查看 stage、進度；在 M6 查看各 trial 的分數、門檻與拒絕原因。

      可以換頁或關頁，伺服器會繼續。要取消就明確取消並等確認，不能按很多次啟動來讓它更快。

      成功標準：run 為 completed，有完整結果與適用範圍；若 failed 或 cancelled，不要把部分結果當完成。

    6. M7：綁定凍結 trial，執行新的閉環

      先選有效 trial。若設備配置尚未建立，回 M3 由該 trial 確認設備型式、拓樸及點位，另存後返回。M7 選「新模擬與工作階段」，核對情境與傳輸路徑，再按「建立凍結模型工作階段」。

      先用「單步推進」看掃描與數值變化，再用「啟動伺服器連續執行」。要暫停，按「本批完成後暫停」並等待 paused／實際停止；恢復需另下明確操作。只換相機、游標或設備動畫，不會推進物理狀態。

      成功標準：session 綁定的模型／情境／設備版本正確，已確認掃描數與曲線更新；完整季度範例應完成 129,600 掃描，不以較短執行冒充。

    7. M8：比較證據，僅把合格候選送審

      同時看品質、偏差、越限和 MV 動作代價，不只看單一分數。選「可送審」方法、精確 Runtime 目標，勾選僅供審查的確認，再按「保存精確目標的候選送審版本」。

      成功標準：審查版本已保存，且明示尚未授權控制。此處結束研究 SOP；接下來必須由獨立核准者走 Runtime 流程。

    PG改用 PostgreSQL：本機已配置的資料來源只查詢資料，不在瀏覽器輸入資料庫密碼。

    在 M2 選「PostgreSQL 歷史資料」，來源選 cement-quarter（Disposable cement quarter），核對 schema public、table cement_raw、時間欄位 observed_at。

    「開始時間 · UTC（包含）」選 2026-01-01 00:00:00；「結束時間 · UTC（不包含）」選 2026-04-01 00:00:00。這裡一律輸入 UTC，不依瀏覽器時區轉換；日期控制項不用另輸入字母 Z。填「資料集名稱」後按「匯入並前往清理」。

    這個來源是本機唯讀 PostgreSQL，匯入後仍須走 M4 清洗及後續資格。查不到此來源，表示伺服器白名單未配置，不是手動輸入任意 DSN 的理由。與 CSV 相同的物理資料，不保證產物 ID 相同。

    06 / RUNTIME FUNCTIONS

    R1–R7：監測、審查與受控操作

    使用 Runtime 入口。先選「已核准控制群組」，再核對來源、模型、instance 與 Epoch。權限看角色加上該 profile 的明確 grant，不只看左下角角色名稱。

    R1設備總覽先確認正在看誰、資料是否新鮮、誰有控制權。

    選「已核准控制群組」，看來源、模型、Epoch、觀測時刻、原生健康及需要處理事項。「重新查詢狀態」是讀取；「查看接管條件」「查看事件」是導航。

    沒有 profile 就請管理者配置，不猜設備或 Tag。最後已知值可能仍顯示，但不能當新鮮量測。good 也不等於已 Engage。

    R2趨勢與診斷把實際值、目標、操作界線與完整預測放在同一時間脈絡。

    選「即時與最新完整預測」或「指定時間歷史」。歷史可用「最近 1 小時／8 小時／24 小時」，或輸入開始／結束（本機時區），再按「查詢歷史」；查詢中可取消。

    使用「製程比較／預測診斷」、曲線排列、逐條選線與共用時間游標。游標可用方向鍵逐筆移動、Home／End 到起終點。不同單位的曲線高度不直接比較。

    查詢限有效的過去時窗且不超過 31 天。缺少歷史預測快照時不回填成已有預測。命令 SP、已應用 SP、PID OP 是不同資料，不能互相替代。

    R3控制操作每次變更都要核對目標、原因、確認畫面及回條。

    檢查控制權、Arming、DCS 接回證據、採集／求解／應用健康與 blockers。生命週期包含基準啟動、事故後監測重建、Monitor、Arm、Engage、Hold、Exit 與交接後停止。

    「CV 目標與操作界線」只允許配置好的變數與界線。填新值及「操作原因」，按「預覽變更，不立即寫入」，核對後才確認；預覽或取消都不是下令。此頁不提供任意 MV SP 寫入。

    完成要有 Operation ID、已確認終態及原生證據。按鈕能點不代表原生安全門檻必定通過。詳見 控制 SOP。

    R4事件與資料健康分清楚事件來源、條件是否解除及命令結果。

    用嚴重度及「只看未讀」篩選，閱讀條件是否仍存在、最近評估及來源，再寫「已讀註記」。「標記已讀／更新已讀註記」只記錄閱讀，不清除聯鎖，也不代替外部 DCS 警報確認。

    持久操作紀錄可按「查詢原生回條，不重送」。unknown 不是成功或失敗的同義詞。清單可能只顯示最多 500 筆，沒看到不代表不存在歷史。

    R5績效與漂移先檢查兩段資料是否真的可以比較。

    設定基準開始／結束、候選開始／結束，按「比較相容工況」。時間窗需順序正確、互不重疊，並核對目標、限制、來源及資料品質。

    先看有效樣本、覆蓋率、壞樣本與缺口，再看偏差、變異、RMSE、越限與 MV 動作。資料不足或不相容時，不應出現可以採信的改善百分比。

    即使可比較，也只是觀察比較，不是因果證明。MV 動作較少不是節能；沒有獨立功率和產量量測，就不能聲稱節能率。

    R6版本與交接核准、安裝、啟動及交接是不同動作。

    在「候選版本」選精確候選，核對模型 SHA-256、目標、適用範圍及證據。非候選建立者且有群組核准權的人，設定「核准到期（本機時區）」後按「核准此版本，不安裝」。

    選未撤銷、未到期的核准，填「發布／撤銷原因」，才能按「安裝至核准主機，不啟動」。沒有運行引擎且已安裝候選時，才使用「以已安裝候選啟動 Monitor」。

    已有引擎改版用「預覽並要求安全交接」，不能再啟動第二個寫入者。沒有獨立「回退」快捷鍵：把原先不可變版本當候選，重新核對有效核准並走同一安全交接流程。

    R6+持續最佳化 · 有界發布政策進階功能，不是無限制自動接管。

    政策限定固定模型、可調參數、工況、觀測條件、冷卻及最多發布次數；另需獨立核准。建立政策先為暫停，啟用不會自行啟動、Arm 或 Engage。

    只在既有健康、已獲授權的 Engage 中執行符合政策的交接。可以「核對並排入上方候選」，但排入、派送與原生接受是不同階段，必須查看同一 job／operation 的結果。

    暫停是停止後續發布，不自動回退既有版本。拒絕、已消耗預算與 unknown 應保留，不用重新建立政策來繞過限制。新手保持暫停。

    R7連線、權限與稽核讀取來源、授權、worker 與儲存容量。

    查看核准來源、scope、profile hash、worker generation、最新觀測與容量。「重新查詢，不重連」是安全的讀取途徑。

    「確認後要求重連共用 OPC worker」會影響全部群組；需要 Admin、所有配置群組的明確維護權，以及每組安全交還且無未解操作。不是一般的重新整理按鈕。

    HTTP 202／queued 只表示排隊，之後須看實際新 generation、連線回報及新鮮來源。容量未知就不能猜；沒有保留策略也不代表系統會自動刪除資料。

    07 / AUTHORIZED CONTROL SOP

    核准與接管：每一步都要有證據

    這一節不是新手自由試按清單。

    第一次使用請由熟悉本機隔離環境的管理者陪同；未受訓或沒有精確群組權限時，只閱讀。以下流程不授予任何工廠控制權，也不取代現場 DCS／安全系統 SOP。

    狀態／動作白話意思不能推論成
    Monitor取得真實資料、建立歷史並觀察求解，不做一般 MV 派送。已完成暖機、已解鎖或已接管。
    Arm操作者明確解鎖接管資格。已開始控制；仍需另一個 Engage。
    Engage通過原生門檻後允許閉環派送，並持續確認應用。只因按鈕已點擊就一定成功。
    Hold停止新的 MPC 控制移動。DCS 已接回、已安全停止程序。
    Exit／Stop經獨立交還證據退出；交接完成後才可停止引擎。關閉 HMI 分頁即可達成。

    1. 先確認目標與權限

      R1 選「已核准控制群組」，核對 disposable-local / cement-test / cement_grinding / CementAcceptance 是你要操作的本機群組；再核對來源、模型、instance、Epoch、時間、資料品質及 R4 事件。不同環境應有各自正確身分，不能套用此例。

      成功標準：來源和對象明確、狀態新鮮、無未解的 blocker。看不到 profile 或狀態未知，停在這裡。

    2. R6：由獨立核准者審查候選

      候選作者先在 M8 完成送審。獨立核准者使用自己的帳號，在 R6 選同一候選、核對模型 SHA-256、精確目標及驗證範圍，設定未來的到期時間，按「核准此版本，不安裝」。角色及該群組的 runtime.approve 授權都要符合。

      成功標準：出現精確候選的有效核准。作者不能自行核准；多點一次或把到期設很遠不是解法。

    3. R6：安裝，但不要把安裝當啟動

      由有部署權的人選未撤銷、未過期核准，填具體原因，按「安裝至核准主機，不啟動」。保存 operation ID，等接受回條，核對安裝版本。

      成功標準：精確版本已安裝；沒有因安裝而自動啟動、Arm 或 Engage。

    4. 依目前狀態選一條路，不重複啟動

      • 沒有引擎：已安裝且有核准時，在 R6 按「以已安裝候選啟動 Monitor」，核對確認畫面並等回條。
      • 已有正確的 Monitor：直接看 R3 目前資格，不要再按一次 Monitor，避免重建歷史或干擾原流程。
      • 已有不同活動版本：交由有權人走 R6「預覽並要求安全交接」，不是另外啟動第二個引擎。若需要真正冷啟動，先依安全交還與停止程序處理舊引擎。

    5. 等待真實 Monitor 暖機

      R3 查看已確認的原生 Monitor、未解鎖狀態及採集／求解／應用證據。此範例 Ts=60 秒、要求 49 筆合格歷史，可能需約 49 分鐘；實際是否完成由原生 history／qualification 決定，不由倒數決定。資料不良、退出重建或再次開始 Monitor 可能使歷史重新累積。

      成功標準：真實歷史達標、狀態健康、版本／Epoch 一致、無 blocker。不要縮短 Ts 或放寬品質來加快。

    6. R3：明確解鎖 Arm

      填「操作原因」，按「明確解鎖 Arm」。在確認畫面重新看對象、設備、版本／Epoch、動作及原因；確認後等原生回條。沒有獲准就取消，不是反覆嘗試。

      成功標準：該 operation 已確認接受，最新狀態為已明確解鎖。此時仍不是 Engage。

    7. R3：另行接管 Engage

      再次確認健康、權限、PID 實際／要求模式、應用回授與命令時效。按「接管 Engage」，核對並確認。持續觀察 CV、MV、目標與限制，保留 operation ID。

      成功標準：操作終態接受、原生狀態確實 Engage，且 PID RCAS 與獨立 applied-SP／命令應用證據符合要求。HTTP 排隊、WebSocket 更新或 SP 暫存器讀回都不夠。

    8. 需要變更目標時，先預覽再送出

      在 R3「CV 目標與操作界線」選操作類型及變數，填有限新值及原因，按「預覽變更，不立即寫入」。核對工程硬界線、目前版本與意圖；取消不派送，確認才派送。

      本機影片曾做細度目標 360→361→360，但這不是通用設定。每次都必須看目前工程契約，不直接照抄；DV 不可當可操作變數，不能任意寫 MV SP。

      成功標準：同一 operation 的接受回條、更新後的原生狀態與後續實際求解相符，不以畫面輸入框變了就算完成。

    R6如何切換版本／回退到原版本？都走精確候選與安全交接，不直接覆寫正在跑的模型檔。
    1. 記下目前 instance、模型 SHA-256、Epoch，以及準備回退的原不可變版本。
    2. 在 R6 選新候選，取得有效的獨立核准，核對適用範圍。
    3. 按「預覽並要求安全交接」，核對目標及原因，確認後等待原生交接與狀態證據；不要另開第二個寫入者。
    4. 成功看活動模型／Epoch 與回條是否一致；失敗或 unknown 走故障處理，不自動再接管。
    5. 要回退，選原先不可變版本，核對或重新取得有效核准，再走同一安全交接流程。沒有「一鍵無條件回退」。
    08 / STOP SAFELY

    離開畫面，不等於停止系統

    請先決定要停止哪一層。不要拿關頁、暫停政策或重連來代替停止控制。

    你想做什麼正確操作要等到什麼
    只離開畫面可以登出／關頁；先知道伺服器工作仍會繼續。沒有「控制已停止」這個結論。
    暫停新模擬M7「本批完成後暫停」。Session 已確認暫停；恢復需另行操作。
    取消研究M1／研究工作中的明確取消操作。伺服器回報 cancelled；不是只送出取消請求。
    停止新的自動研究／發布分別暫停 M9 研究政策／R6 發布政策。政策新狀態確認；已在途工作／派送另行查核。
    停止新的 MPC 移動R3「暫停新控制移動 Hold」。接受回條及新狀態；還必須另外確認 DCS 接回。
    安全退出控制依獨立交還證據，R3「退出並交還 DCS」。未解鎖、無待應用、DCS 接回等原生證據成立。
    停止引擎與整套本機服務交還完成後「交接後停止引擎」；再在原啟動終端按 Ctrl-C。引擎停止確認、啟動器結束自己持有的程序並保留產物。
    Hold 不是急停按鈕，也不是 DCS 已接手的保證。

    若控制／通訊結果未知，先依已核准的安全流程處理並由管理者核對；不要用強殺程序、直接關 WSL 或刪檔案來取得一個「已停止」外觀。工廠安全處置以現場 DCS／安全系統程序為準。

    本機整套服務由前景啟動器管理。正常結束會保留研究、資料庫及操作回條，下次不必重新 prepare。如果服務不是從你目前的終端啟動，找原啟動者／管理者，不要用廣泛的 kill 指令。

    09 / WHEN SOMETHING BLOCKS YOU

    卡住時，先保存證據，再處理原因

    看到什麼先做什麼不要做什麼
    網址無法連線核對端口、Ubuntu／WSL 是否運行及原啟動終端。WSL 內可讀取而 Windows 不通時，請管理者檢查 localhost 轉送、防火牆／代理。不要先改成 0.0.0.0、關閉安全檢查或開放外網。
    找不到 pg_ctl／Wine在 Ubuntu Bash 使用本手冊的完整 PATH 設定；核對 tools.json 與工具檔是否還在。不要混用 PowerShell 語法或自行改全系統工具。
    地址已使用／launcher lock很可能已有同一套服務。先開原網址並詢問啟動者。不要刪 lock、殺掉不明 PID 或啟動第二個 writer。
    登入失敗／沒有可見 profile核對研究／Runtime 入口及管理者交付的帳密、角色與 profile scope。不要刪 identities.db、改使用者 ID，或以 Admin 名稱推論權限。
    資料不可用／辨識不合格讀錯誤、時間／品質／單位與 qualification report；修正來源或建立新的合法版本。不要將缺口補成假資料，或放寬門檻只為通過。
    工作一直 queued／running查看原 run／session ID、實際階段與完成數，必要時明確取消並等確認。不要靠多次啟動、關頁或換頁加速。
    Monitor 不能 Arm／Engage看真實 history、品質、版本／Epoch、PID、應用回授與 blockers。不要縮短 Ts、偽造歷史或以按鈕外觀代替資格。
    SP 命令時間很舊Monitor／Hold 可能沒有新派送。分開核對 actual／applied-SP、PID 模式及來源健康，不能只看命令暫存器。不要因此自行寫一個 MV SP「測試看看」。
    rejected／版本或核准過期讀拒絕原因，重新核對精確版本、Epoch、核准及權限，合法排除後才建立新意圖。不要無限重試、重用過期確認或換目標碰碰運氣。
    unknown／請求逾時保留 operation ID，到 R4「查詢原生回條，不重送」，並依安全程序核對當前控制權。不要假設失敗、換新 ID 重送，或直接把紀錄改成成功。
    比較沒有改善百分比檢查時窗、來源、工況、目標／界線、覆蓋率與缺口。不要把不相容資料或 MV 動作量換算成節能率。
    3D 黑屏／WebGL 失效先用點位與趨勢確認資料；檢查瀏覽器圖形支援，按介面提供的重試恢復繪圖。不要把 3D 故障當控制器已停止，或重送 Session 操作。
    重連顯示 queued／202R7「重新查詢，不重連」，等實際新 generation、連線回報與來源時間。不要把排隊當連線已成功，也不要連續點重連。
    ADMIN事故後恢復：只由管理者處理恢復 Monitor，不自動恢復 Arm／Engage。
    1. 保留原 operation／run ID、UTC 時間、錯誤及拒絕回條；先查原操作結果，不重送。
    2. 管理者核對原程序身分及退出狀態、writer lock／authority socket、獨立 DCS 交還與目前安全基線。可連線的原程序不能當作已死掉。
    3. 視可用 UI 與程序狀態，使用 R3「事故後重建監測程序」；只有整套工作區確實停止且舊程序已獨立確認退出時，才在同一啟動命令末尾明確加 --recover-monitor。
    4. 該選項恢復投運原始 baseline Monitor，不自動載入候選、不 Arm／Engage；仍保留可連線檢查及 writer lock。它也不是要刪除舊 socket／journal 的許可。
    5. 等新的未解鎖 Monitor 真實暖機。若需要安全基線核對，須有新鮮獨立證據及相應權限；解除新操作阻擋不會把原 unknown 改寫為成功。

    不要在啟動失敗時機械式加入此旗標。管理者需記錄「為何確認原程序已退出、誰持有寫入權、DCS 如何確認接回」。

    回報問題時帶這些，不帶帳密

    • 使用哪個入口、頁面編號、UTC 時間、預期與實際結果。
    • profile／模型／Epoch、run／session／operation ID，以及完整拒絕文字。
    • 本機根目錄內相應的 launch-*.json、native-start-*.json、拒絕回條與服務日誌；由管理者先遮蔽秘密再分享。
    • 不要分享帳密 JSON、私鑰、session cookie、認證資料庫或整個工作區壓縮檔。

    11 / PLAIN-LANGUAGE GLOSSARY

    看不懂縮寫時，回來查這裡

    APC／MPC／DMC
    進階控制／模型預測控制／其中一種步階反應控制方法。模型先預測，再在限制內選擇控制移動，不是單純把畫面數值改成目標。
    HMI
    人操作與看狀態的網頁介面。關掉 HMI，不會自動停止後端控制。
    CV：要控制好的結果
    例如產品細度、磨機差壓。看實際值相對目標的偏差、波動與越限。
    MV：能調整的手段
    例如進料或分離器速度的有效設定值。有最大／最小值及每步可移動幅度。
    DV：看得到但不能直接操控的擾動
    例如硬度、含水率。拿來預測其影響，不把它當成操作旋鈕。
    SP／PV／OP／applied-SP
    SP 是設定；PV 是量測；OP 是 PID 輸出；applied-SP 是獨立確認已應用的設定。讀回 SP 暫存器不等於機械／PID 已採用。
    PID／RCAS／DCS
    PID 是下層控制；RCAS 是下層允許遠端串級設定的模式；DCS 是原控制系統。HMI 的接管請求還需要實際模式與交還證據。
    Ts／P／M
    Ts 是每次控制的時間間隔；P 是預測多少步；M 是規劃多少步控制。它們是工程設定，不是畫面更新速度。
    Study／Run／Trial／Session
    Study 固定研究條件；Run 是一次研究執行；Trial 是其中一組參數試驗；Session 是綁定模型、情境與設定的一次原生孿生工作階段。
    Profile／SHA-256／Epoch／Instance
    Profile 定義精確控制範圍與授權；雜湊辨識不可變內容；Epoch 區分控制狀態版本；Instance 區分原生程序身分。不能只看顯示名稱。
    Qualification／Blocker
    Qualification 是是否具備使用資格的證據；Blocker 是目前不能往下執行的原因。不是需要忽略的提醒。
    Operation ID／Accepted／Unknown
    每個操作的追蹤身分／已確認的接受終態／原結果不能確定。Unknown 要查原回條，不可當沒發生而重送。
    Training／Validation／Test
    先用訓練資料建立模型，用驗證資料選參，最後用未拿來選參的留出資料評估。已看過的 test 不能重新標為未觸及。
    偏差／變異／RMSE／越限
    偏差看長期偏離，變異看波動，RMSE 看整體誤差，越限看違反界線。不能只挑其中一個好看的數字。
